## 三、测试中发现并修复的问题

| 问题 | 影响 | 修复 |
|---|---|---|
| 后端 Docker 镜像一开始只复制旧 jar，未包含当前源码 | 页面测到旧逻辑，任务收件箱未显示未提交学生 | 执行 `mvn test package` 后再 `docker compose up -d --build backend`，并在报告中记录正确测试方式 |
| 含人工题的学习单提交后被自动标记为 `graded` | 教师工作台“待评分”为 0，人工题可能被漏批 | 修改 `TaskServiceImpl`：只有全题目可自动批改时才自动置为 `graded`；含人工题保持 `submitted` |
| 学生访问 `/api/tasks/{taskId}/my-result` 返回 403 | 学生无法查看批改详情 | 修改 `SecurityConfig`，将 `/api/tasks/*/my-result` 放行给学生角色，并新增安全测试 |

## 六、2026-08-11 补充回归：完整提交生命周期与并发

本轮使用场景编号 `0811134739`，后端、数据库和文件服务均运行在 Docker 中。先以默认“无 Redis”模式模拟 30 名学生集中提交，再启用 Compose `cache` profile 以 10 名学生复跑同一套流程。

### 1. 覆盖的真实操作

1. 教师创建课程、学期、课时、课堂任务、考试试卷、考试和个人项目，并准备课程资源目录与文件。
2. 学生登录，下载课程资源，在个人网盘创建目录并上传/下载文件；另一名学生访问该网盘文件返回 HTTP 403。
3. 30 名学生并发提交课堂任务，教师看板最终统计 30 份且实时事件合并刷新，不按每个事件单独请求。
4. 教师按完整学生名单进入任务、考试、项目批改；名单包含未提交学生、班级、学号、提交时间、状态、成绩和修订次数。
5. 教师退回任务、考试、项目并填写原因；学生看到原因后修改重交；旧总分和旧维度分不继续参与统计。
6. 教师完成批改后，学生只能查看自己的只读结果；再次覆盖提交返回 HTTP 409。

### 3. 本轮发现并修复的问题

| 问题 | 用户影响 | 修复结果 |
|---|---|---|
| 业务异常统一返回 HTTP 200 | 前端无法可靠区分越权、未找到和冲突 | 400/401/403/404/409/500 返回真实状态 |
| Docker JVM 使用 UTC | 考试开始时间与课堂本地时间错位 | 默认 `Asia/Shanghai`，支持 `APP_TIME_ZONE` 配置 |
| 学生项目页没有批改详情 | 只能看到“已批改”，看不到具体得分 | 增加总分、四维度分和备注只读详情 |
| 登录请求附带本地旧 token | 已过期会话可能阻断重新登录 | 登录和公开请求不再注入认证头 |
| 已批改考试仍显示倒计时/草稿状态 | 学生误以为还能继续答题 | 改为“已批改 + 成绩”的只读结果状态 |
| 项目/考试详情直接显示英文状态 | 页面语义不统一 | 统一状态映射和状态标签 |
| 手机项目按钮高度约 28px | 触控困难 | 主操作区最小高度调整为 44px |

详细的小白操作说明和全部截图见 `docs/用户操作指南.docx`。
